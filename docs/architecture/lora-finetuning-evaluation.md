# 个人数据微调评估 · LoRA 可行性（预算与效果双评估）

> 文档编号：AR-06 ｜ 需求：REQ-202610-0967（backlog M7-08）｜ 依赖：M7-06 模型路由
> 评估日期：2026-10-22 ｜ 复跑工具：`cd vps && python -m app.lora_eval report`

## 1. 结论摘要

**结论：技术上可行，当前不建议进入生产；先补数据与评测基线，再决定是否做一次低成本云端试验。**

| 维度 | 结论 |
| --- | --- |
| 本机训练 | ❌ 不可行：本机无独立 GPU，2G AI 预算只覆盖推理；1.5B QLoRA 也需约 3.5G 显存 |
| 云端训练 | ✅ 预算不是瓶颈：1.5B QLoRA 训练 2000 样本约 **0.3 GPU 小时 / ¥1**；7B 约 **1.1 GPU 小时 / ¥3** |
| 本机推理 | ⚠️ 仅 1.5B 可部署（q4 约 1.3G ≤ 2G）；3B（约 2.1G）与 7B（约 4.7G）超预算 |
| 数据条件 | ❌ 当前运行库 0 条收藏 / 0 条摘要，远低于最低 500 条可用样本 |
| 效果证据 | ⚠️ 尚无留出集与基线评分；LoRA 相对提示词 / RAG 的增量未知 |
| 建议 | 先做数据积累与评测协议；达到 500 条可用样本后，用 ≤¥300（实际约 ¥1）做一次 1.5B QLoRA 对照实验；7B 暂不纳入本轮 |

> 一句话：**卡点不是 GPU 租金，而是个人数据量与效果证据。** 在没有 500 条以上高质量样本和冻结评测集之前，训练只会得到无法证明有效的适配器。

## 2. 个人数据画像

### 2.1 可用数据资产

| 数据 | 位置 | 可构造的样本 | 质量 / 风险 |
| --- | --- | --- | --- |
| 收藏仓库元数据（名称 / 简介 / 语言 / Star） | VPS `my_repositories`、D1 | 指令 → 结构化标签 / 分类 | 字段稀疏，需清洗 |
| README 摘要（人工确认前后） | `repo_readmes`、`summary_samples` | README → 中文摘要（SFT） | 现有摘要由 1.5B 模型生成，直接蒸馏会放大原有错误 |
| 分类树 / 标签 | `categories`、`repo_tags` | 摘要 → 业务线分类 / 标签 | 标签覆盖不均，长尾类别样本少 |
| 推荐反馈（收藏 / 忽略 / 点击） | `recommendation_feedback` | 偏好对（chosen / rejected） | 点击不等于偏好，需过滤；负样本噪声大 |
| 推送记录 | `push_events` | 打开 / 忽略偏好 | 仅作辅助信号，不宜单独训练 |

### 2.2 样本量门槛

`lora_eval.assess_dataset()` 采用以下口径（可用样本 = 摘要样本 + 反馈偏好对）：

| 档位 | 可用样本 | 含义 |
| --- | --- | --- |
| `insufficient` | < 500 | 不足以训练有意义的 LoRA，优先补数据 |
| `minimum` | 500–1999 | 可做一次受控试验，但需强正则与早停 |
| `recommended` | ≥ 2000 | 可支撑风格 / 格式适配的稳定训练 |

**当前实测（2026-10-22）**：本机运行库 `my_repositories` 0 条、`recommendations` 0 条，未导入任何收藏，处于 `insufficient`。因此本报告的预算结论是「如果数据到位要花多少钱」，而不是「现在就能开训」。

### 2.3 隐私边界

- 个人收藏、私有仓库、README 全文均属私有数据，**默认不出本机**；
- 云端 GPU 训练会把训练样本上传到供应商，属于数据出机，必须满足以下任一条件后才可执行：
  - 只使用公开仓库的元数据与公开 README，剔除私有仓库、token、内部地址；
  - 使用支持「不持久化 / 专属实例」的供应商，并签署数据处理条款；
  - 由维护者提供自建 GPU 机器。
- LoRA 适配器本身可能记忆训练样本，导出 / 分享前需做成员推断风险评估。

## 3. 技术路线与底座选型

### 3.1 为什么是 QLoRA

| 路线 | 训练显存（7B） | 本机可行性 | 说明 |
| --- | --- | --- | --- |
| 全参微调 | ≥ 80G | ❌ | 需要多卡 / DeepSpeed，个人项目不划算 |
| LoRA（bf16） | ≥ 18G | ❌ | 24G 卡可跑，但本机无 GPU |
| **QLoRA（4bit + LoRA）** | **约 8G** | 云端可行 | 效果接近 LoRA，24G 卡余量充足 |
| 提示词 / RAG | 0 | ✅ | 零训练成本，应作为第一基线 |

### 3.2 底座候选

| 模型 | 参数 | QLoRA 训练显存 | q4 推理驻留 | 许可证 | 判断 |
| --- | --- | --- | --- | --- | --- |
| Qwen2.5-1.5B-Instruct | 1.5B | 约 3.5G | 约 1.3G | Apache-2.0 | ✅ 本机可部署，首选试验对象 |
| Qwen2.5-3B-Instruct | 3B | 约 5G | 约 2.1G | Apache-2.0 | ⚠️ 略超 2G 推理预算 |
| Qwen2.5-7B-Instruct | 7B | 约 8G | 约 4.7G | Apache-2.0 | ⚠️ 效果更好，但本机无法部署 |
| Llama 3.1 8B Instruct | 8B | 约 9G | 约 5.0G | Llama 3.1 Community | ⚠️ 中文需额外评测，许可证有商用条款 |

选型原则：**训练模型与部署模型必须一致**。若最终只能在本机跑 1.5B，就不要用 7B 做试验，否则效果无法落地。1.5B 的容量有限，适合「摘要风格 / 输出格式 / 分类口径」适配，不适合注入大量新知识；知识型需求应继续走 RAG。

### 3.3 与 M7-06 模型路由的衔接

微调产物不替换默认模型，而是注册为任务级路由：

```
task=summary            → qwen2.5:1.5b-instruct-q4_K_M（默认）
task=summary_style_lora → qwen2.5-1.5b + lora-adapter（试点，失败回退默认）
task=tagging            → 规则 / 1.5B；LoRA 仅在 F1 显著提升时启用
```

路由层需记录 `model_id + adapter_version + eval_report_id`，任一评测指标回退即自动切回默认模型。待 M7-06 模型路由落地后按其注册表扩展；本需求不修改路由代码。

## 4. 预算评估

### 4.1 本机训练：不可行

| 项目 | 数值 | 说明 |
| --- | --- | --- |
| GPU 显存 | 0G | 本机为 CPU 推理节点，无独立显卡 |
| 1.5B QLoRA 最低显存 | 约 3.5G | 仅权重 + 激活 + 优化器状态，未含碎片 |
| 500 样本 × 3 epoch CPU 训练时长 | 约 11 小时 | `lora_eval` 估算；实际可能更慢且占用全部 CPU |
| 结论 | ❌ | 会挤占 API / 爬虫 / 摘要任务，违反 4G 资源预算 |

即使强行在 CPU 上训练，11 小时起的满负载也会与同机其他任务争抢 CPU，不可接受。

### 4.2 云端训练：按量付费，成本很低

按 RTX 4090 24G、¥2.5/小时、800 token/样本、3 epoch、QLoRA rank=16 估算：

| 模型 | 样本数 | Token 总量 | GPU 小时 | 费用（元） |
| --- | --- | --- | --- | --- |
| Qwen2.5-1.5B | 500 | 1.2M | 0.07 | 0.18 |
| Qwen2.5-1.5B | 2,000 | 4.8M | 0.29 | 0.74 |
| Qwen2.5-1.5B | 10,000 | 24M | 1.47 | 3.68 |
| Qwen2.5-7B | 2,000 | 4.8M | 1.09 | 2.72 |
| Qwen2.5-7B | 10,000 | 24M | 5.45 | 13.63 |

> 估算含 25% 数据加载 / 验证开销；实际受序列长度、batch、梯度检查点与供应商虚标影响，建议按 2–3 倍预留。即便如此，单次试验仍远低于 ¥300 上限。

### 4.3 本机推理：只有 1.5B 放得下

| 模型 | q4 驻留 | 2G 预算 | 结论 |
| --- | --- | --- | --- |
| Qwen2.5-1.5B | 约 1.3G | ✅ | 可与 bge-m3 串行复用同一预算 |
| Qwen2.5-3B | 约 2.1G | ❌ 略超 | 需压缩上下文或把 AI 预算提到 2.5G |
| Qwen2.5-7B | 约 4.7G | ❌ | 只能云端推理，或本机加内存 |

### 4.4 存储与人力

| 项目 | 估算 | 说明 |
| --- | --- | --- |
| LoRA 适配器 | 40–180 MB | 1.5B 约 40M，7B 约 160M |
| 合并后 q4 模型 | 1.0–4.7 GB | 仅部署时需要；本机磁盘配额 4G，7B 放不下 |
| 训练 checkpoint | 适配器 × 2 + 日志 | 约 150–400 MB |
| 数据准备 / 清洗 | 2–4 人日 | 去重、脱敏、构造指令对、划分留出集 |
| 盲评 | 2–3 人日 | 4 个任务 × 100 样本，双人交叉复核 |

**人力成本远高于 GPU 租金**，这是本评估最重要的预算结论：不要为了省几块钱 GPU 而跳过评测设计。

## 5. 效果评估协议

### 5.1 评测任务与指标

| 任务 | 留出集 | 主指标 | 次指标 | 通过门槛 |
| --- | --- | --- | --- | --- |
| README 中文摘要 | 100 个未参与训练的仓库 | 盲评胜率（微调 vs 基线） | 准确性 / 完整性 / 简洁性 / 流畅度（1–5） | 胜率 ≥ 60%，且均值 +5 分 |
| 自动标签 | 300 个已标注仓库 | Micro-F1 | 长尾类别 Recall | F1 +5 个百分点 |
| 业务线分类 | 300 个已标注仓库 | Top-1 Accuracy | 混淆矩阵 | 准确率 +5 个百分点 |
| 推荐理由 | 100 对推荐 | 盲评胜率 | 具体性 / 可信度 | 胜率 ≥ 60% |

### 5.2 样本量与显著性

`compare_effect()` 使用**精确二项符号检验**（双侧，p=0.5），默认 α=0.05、最小可感知差异 5 分（百分制）：

- 100 对样本中 60 胜 40 负：p≈0.045，达到显著；
- 100 对中 55 胜 45 负：p≈0.32，不显著；
- 因此每个任务至少 **100 对有效样本**，推荐 150–200 对以抵消剔除。

### 5.3 防泄漏与可复现

1. 按 `repo_id` 划分训练 / 验证 / 测试，禁止同一仓库的 README 片段跨集合；
2. 先冻结测试集与评分 rubric，再开始训练；评测脚本与随机种子入库；
3. 基线必须是「同一底座 + 提示词 / RAG」，而不是旧版小模型，否则无法区分是微调还是换模型带来的提升；
4. 盲评时隐藏模型来源，双人独立打分，分歧 > 1 分时第三人仲裁；
5. 训练 3 个随机种子，报告均值与标准差；单次跑赢不算数。

### 5.4 评测命令

```bash
# 每个任务一份配对评分 JSON（百分制），长度必须一致
cd vps
.venv/bin/python -m app.lora_eval compare \
  --baseline eval/baseline-summary.json \
  --tuned eval/tuned-summary.json \
  --min-effect 5
```

输出包含均值差、胜 / 平 / 负、胜率与 p 值；`verdict=improved` 才进入试点。

## 7. 结论与触发条件

### 7.1 结论

1. **本机训练不可行**：无 GPU，CPU 训练会挤占整机资源；2G 预算只够推理。
2. **云端训练很便宜**：1.5B/7B 单次试验在 ¥1–15 量级，¥300 上限绰绰有余；真正的成本是数据准备与盲评人力。
3. **本机只能部署 1.5B**：3B/7B 的 q4 驻留超过 2G，部署前必须调整硬件或预算。
4. **当前数据不足**：运行库 0 条收藏，未达到 500 条最低样本量；此时训练没有统计意义。
5. **效果未知**：没有冻结留出集与基线评分，不能承诺 LoRA 一定优于提示词 / RAG。

### 7.2 进入试验的触发条件（全部满足）

- [ ] 可用样本 ≥ 500（摘要 + 反馈偏好对），且至少 100 对独立留出样本；
- [ ] 基线（同底座 + 提示词 / RAG）在 4 个任务上的评分已冻结；
- [ ] 数据脱敏完成，云端训练获得维护者明确授权；
- [ ] 单次试验预算 ≤ ¥300，实际预估 ≤ ¥15；
- [ ] 预注册评测协议与通过门槛（本报告 §5）。

### 7.3 试点转正条件

- 至少 2 个任务达到 §5.1 门槛，且 p < 0.05；
- 1.5B 适配器在本机 2G 预算内稳定运行 7 天，无 OOM / 明显延迟回退；
- 路由层可一键回退默认模型，回退演练通过。

任一条件不满足：保持默认模型 + 提示词 / RAG，不进入生产。

## 9. 风险与边界

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 摘要训练数据由 1.5B 模型生成 | 蒸馏放大错误，微调后更自信地犯错 | 用人工确认样本；混入原始 README 对照 |
| 反馈负样本噪声 | 学到「点击 ≠ 喜欢」的错误偏好 | 只用收藏 / 忽略作为强信号，点击降权 |
| 云端数据出机 | 隐私泄露 | 脱敏 + 公开数据 only + 供应商条款 |
| 过拟合小数据 | 留出集提升、线上无感 | 强正则、早停、3 seed、线上 A/B |
| 底座升级 | 适配器失效 | 锁定底座版本；路由记录 adapter_version |
| 评测人力不足 | 盲评样本不够，结论不显著 | 先做 100 对最小可用评测，再扩到 200 |

**本需求边界**：不实际训练、不引入 GPU / torch 依赖、不改变默认模型路由；只交付可复跑的评估工具与决策报告。实际训练需另立需求并取得数据出机授权。
