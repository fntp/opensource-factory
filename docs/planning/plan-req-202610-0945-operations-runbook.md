# 实施计划 · REQ-202610-0945 运维手册（部署 / 升级 / 回滚 / 故障处理 SOP）

> 需求：REQ-202610-0945（backlog M5-07）｜ 分支：`feat/req-202610-0945-operations-runbook`
> 依赖：M5-01 正式部署（REQ-202610-0939）
> 目标：把分散在部署基线、正式部署、资源预算等文档中的运维动作，收敛为一份可执行、
> 可演练、可审计的运维手册；同时提供一个只读的现场诊断脚本，缩短故障定位时间。

## 1. 现状与缺口

- `docs/guides/deployment-baseline.md` 覆盖运行目录、Redis、systemd 与首次部署；
- `docs/guides/production-deployment.md` 覆盖三端正式部署与单组件回滚；
- `docs/guides/resource-budget-verification.md` 覆盖 4G / 15G 资源实测；
- 但缺少统一入口回答「日常怎么巡检、版本怎么升级、失败怎么回滚、事故怎么分级与复盘」，
  也没有标准化的现场信息采集手段，故障时容易漏看日志 / 资源 / 版本信息；
- 升级与回滚步骤散落在多份文档，缺少发布前检查单、回滚触发条件与数据库不可回滚的明确提示。

## 2. 方案总览

```
docs/guides/operations-runbook.md（GD-06，唯一运维入口）
  ├─ 系统全景 / 角色与变更纪律
  ├─ 日常巡检（日 / 周 / 月）
  ├─ 部署 SOP（首次 / 常规 / 分组件 / 失败处理）
  ├─ 升级 SOP（评估 → 备份 → 发布 → 观察）
  ├─ 回滚 SOP（edge / admin / vps / 数据库）
  ├─ 故障处理 SOP（分级 / 五步法 / 场景手册 / 复盘）
  ├─ 备份恢复 / 安全密钥 / 监控告警
  └─ 附录：命令速查 / 变更单 / 复盘模板

deploy/scripts/ops-diagnose.sh（新增，只读）
  └─ 一键收集版本、systemd 状态、健康检查、日志尾部、资源与磁盘占用
      → 输出权限 700 的诊断目录，供故障处理与复盘使用
```

设计要点：

- **文档即 SOP**：每一步给出可直接复制的命令、期望结果与失败分支，避免「凭经验操作」；
- **不可逆操作前置备份**：升级 / 回滚 / D1 迁移前必须先做 SQLite 与 D1 备份，并在变更单记录回滚点；
- **回滚分级**：代码回滚、配置回滚、数据恢复分开决策；D1 迁移默认只前进不回滚，数据恢复必须停服；
- **故障处理先止血**：先确认影响面、保留现场、恢复服务，再做根因分析；P0/P1 必须复盘；
- **只读诊断**：`ops-diagnose.sh` 不修改配置、不重启服务、不读取 `.env` 明文，输出目录 700；
- **防漂移**：新增测试校验手册必需章节、关键命令、索引链接与脚本 `--help`，文档与脚本变更时同步失败。

## 4. 手册章节

1. 使用说明与适用范围、相关文档矩阵；
2. 系统全景：组件、入口、端口、数据与版本标识；
3. 角色、值班、变更分级与变更单；
4. 日常巡检：每日 / 每周 / 每月检查单与记录模板；
5. 部署 SOP：首次部署、常规发布、分组件部署、部署后验收、失败处理；
6. 升级 SOP：兼容性评估、升级前检查、标准步骤、D1 迁移、配置变更、观察期；
7. 回滚 SOP：触发条件、决策矩阵、edge / admin / vps / 数据库分组件步骤、回滚后验证；
8. 故障处理 SOP：P0–P3 分级、五步法、快速诊断、场景手册、事故复盘模板；
9. 备份与恢复 SOP：备份对象 / 频率 / 保留、SQLite 与 D1 导出、恢复步骤、演练；
10. 安全与密钥 SOP：密钥清单、轮换步骤、泄漏处置、访问控制；
11. 监控与告警：健康检查、日志、资源红线、Workers Analytics、告警路由；
12. 附录：命令速查、端口与环境变量、变更单模板、复盘模板。

## 5. 测试与验收

| 层 | 用例 |
| --- | --- |
| vps | `tests/test_operations_runbook.py`：必需章节 / 关键词、关键命令、索引与 backlog 链接、脚本 `bash -n` / `--help`、无明文密钥 |
| deploy | `test_deploy_assets.py` 既有脚本 `bash -n` 自动覆盖新增脚本 |
| 手工 | `deploy/scripts/ops-diagnose.sh --no-services --output /tmp/...` 生成摘要；`--help` 可读 |

验收标准：

1. 运维手册覆盖部署、升级、回滚、故障处理四类 SOP，且每类都有检查单与失败分支；
2. 所有命令均能在当前仓库找到对应脚本或系统命令，不引用未落地的脚本；
3. 回滚章节明确区分代码 / 配置 / 数据库，并写明 D1 迁移不可自动回滚；
4. 故障处理章节包含 P0–P3 分级、通用五步法与不少于 10 个常见场景；
5. 文档索引、backlog、roadmap、task-planning 同步更新；
6. `vps` 全量 pytest 通过，新增脚本 `bash -n` / `--help` 通过。

## 6. 风险与后续

- **文档漂移**：脚本或部署形态变化后手册可能过期；用测试锁定关键命令与链接，并在变更单模板中要求同步手册；
- **单机口径**：当前为单 VPS + Cloudflare 无状态控制面，手册不覆盖多节点 / 多区域；扩容后需补充负载均衡与 Redis 全局限流章节；
- **备份自动化待合入**：M5-04 备份脚本合入后，第 9 节应优先引用其封装命令，保留本节手工命令作为兜底；
- **监控自动化待合入**：M5-03 告警接口合入后，第 11 节补充告警路由与静默操作；
- **RTO / RPO 未定**：在 `docs/requirements/open-questions.md` 登记 Q18，待维护者确认目标值与值班联系方式。
