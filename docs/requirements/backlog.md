# 需求池（需求列表）· Backlog

> 来源需求：REQ-202610-0462（需求调研，分析项目后续需求） ｜ 维护人：fntp ｜ 更新方式：需求状态变化时更新
>
> 本文件是 OpenFactory 的**需求唯一入口（需求池）**：后续所有迭代需求在此登记、排期与跟踪。平台立项后由平台分配 `REQ-*` 编号；本文件保留内部代号 `M<里程碑>-<序号>`。

## 1. 背景与目标

- **背景**：项目已完成立项（REQ-202610-0454 / M0）——三端骨架（admin / edge / vps）、规范与文档体系、参考项目能力移植均已就位；当前仍以「演示模式 + 本地兜底」运行，真实数据链路与正式部署尚未打通。
- **终局目标（规划口径）**：保守估计，经 **1300+ 次迭代**，把项目打磨为**非常成熟、依托于个人数据**的开源项目；token 不限量，以质量为先、精细打磨。
- **资源约束**（详见 [resource-plan.md](../planning/resource-plan.md)）：部署于本机；内存约 4G（前后端应用 2G + AI 推理 2G）；磁盘约 15G；源码只含公开配置，私有配置仅存本机。
- **本轮产出**：把「后续要做什么」完整回填为可排期的需求列表（92 条 + 常设轨道），并给出迭代预算与管理机制。

## 2. 规划原则

1. **小步迭代**：1 需求 ≈ 1 迭代 ≈ 1 个 `feat/req-*` 分支，单一可验证闭环，主干随时可用；
2. **质量优先**：token 无成本上限，验证 / 测试 / 打磨范围不因成本缩减；
3. **降级优先、本地优先**：外部依赖（模型 / 站点 / 云服务）必须有兜底路径；AI 推理与私有数据留在本机；
4. **资源红线**：一切实现必须在 4G 内存 / 15G 磁盘预算内运行（模型选型、并发度、缓存策略均受此约束）；
5. **单一事实来源**：状态流转同步本文件与 [task-planning.md](../planning/task-planning.md)。

## 3. 状态、优先级与编号

- 状态：`待排期 → 已排期 → 开发中 → 待验证 → 已完成 / 已取消`（同需求规范）；
- 优先级：`P0` 主链路阻塞 ｜ `P1` 核心能力 ｜ `P2` 增强与体验；
- 编号：内部代号 `M<里程碑>-<序号>`；平台立项时分配 `REQ-YYYYMM-NNNN`（映射关系在 task-planning 记录）。

## 6. 需求池管理机制

1. **登记**：新需求先入池（本文件），标注来源（维护者 / 运行观察 / 用户反馈 / 技术债）与优先级；
2. **排期**：按里程碑与依赖在 [task-planning.md](../planning/task-planning.md) 排期，形成迭代（`IT-XXXX`，全局递增）；
3. **流转**：状态变化时同步更新本文件与 task-planning.md；完成后保留记录（含提交哈希）；
4. **评审**：每个里程碑回顾时重排优先级；[open-questions.md](./open-questions.md) 中问题确认后，调整受影响条目；
5. **范围控制**：范围外需求不塞入当前迭代，另开编号（同需求规范 §6）。
